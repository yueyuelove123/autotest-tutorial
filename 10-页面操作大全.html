    第 10 章 页面操作大全¶

    本章目标

    • 会按场景选对输入方法，分清 fill、press_sequentially、press 各管什么；
    • 会操作下拉框、复选框、单选按钮、日期输入框；
    • 会双击、右键、悬停、拖动和滚动；
    • 会处理浏览器自带的 alert、confirm、prompt 弹窗；
    • 会上传文件、验证下载文件的内容；
    • 会处理新标签页和 iframe 里的页面；
    • 把这些操作串成完整的表单用例。

    上一章把「找到元素」讲透了，这一章讲「找到之后做什么」。练习网站专门准备了一页练习场 http://127.0.0.1:8000/lab.html，不需要登录，集中了各种交互控件，本章大部分操作都在它上面实测。个人中心（上传头像）和订单页（导出 CSV）需要先登录，用第 11 章 11.3 节的 logged_in_page 夹具种 cookie，这里先直接用。

    第 11 章 11.6 节讲弹窗、新标签页、iframe、上传下载时，练习网站还没有这些功能，当时只演示了写法；这一节起全部可以在练习网站上真跑一遍。

    10.1 输入类¶

    10.1.1 fill：往输入框里放值，默认选择¶

    fill 一步完成「等可操作 → 清空 → 填入 → 触发 input 事件」，是输入的首选：

    page.get_by_test_id("kbd").fill("hi")
print(page.get_by_test_id("kbd").input_value())   # hi

    再 fill 一次会整体替换，不是追加；传空字符串就是清空。clear() 方法也清空，两者等价。

    注意 fill 的原理：它直接设置输入框的值，只触发 input 事件，不会产生 keydown 等键盘事件。这一点什么场景下有影响，看下一小节。

    10.1.2 press_sequentially：一个字一个字地敲¶

    有些输入框不只要「值」，还要「敲键盘的动作」：搜索框输入时每敲一个字都弹联想词，有的页面监听 keydown 做快捷键。练习场的键盘输入框会监听 keydown，把按到的键显示出来。分别用 fill 和 press_sequentially 填 hi，看右边 key-result 的反应：

    page.get_by_test_id("kbd").fill("hi")
print(repr(page.get_by_test_id("key-result").inner_text()))   # ''

page.get_by_test_id("kbd").fill("")
page.get_by_test_id("kbd").press_sequentially("hi")
print(repr(page.get_by_test_id("key-result").inner_text()))   # '你按了 i'

    fill 之后是空字符串——页面的 keydown 监听一次都没触发；press_sequentially 之后显示「你按了 i」——它是逐字符发送完整的按键事件（keydown、input、keyup），页面显示的是最后按下的 i。加 delay=100 可以每个字符之间停 100 毫秒，更像真人输入，联想型输入框需要这个间隙。

    顺带说一个旧写法：locator.type() 是老版本的逐字符输入，在当前的 Playwright 版本里已经被官方标记为过时，文档建议用 fill，要逐字符就用 press_sequentially。看到老代码里的 type()，按场景替换成这两个之一即可。

    10.1.3 press：按单个键和组合键¶

    press 模拟按一次键，特殊键用名字：

    page.get_by_test_id("kbd").press("Control+A")
print(repr(page.get_by_test_id("key-result").inner_text()))   # '你按了 A'
page.get_by_test_id("kbd").press("Enter")
print(repr(page.get_by_test_id("key-result").inner_text()))   # '你按了 Enter'

    在输入框里按回车提交表单（第 8 章 8.6 节用过）、Control+A 全选后输入覆盖，都是 press 的日常用法。按键名字规范：Enter、Tab、Escape、ArrowDown、Control+A（Mac 上写 Meta+A 或 ControlOrMeta+A）。

    10.1.4 三种写法怎么选¶

    场景 用什么
    普通输入框填值 fill
    搜索联想、每次按键都有反应的框 press_sequentially，必要时加 delay
    回车提交、快捷键 press
    只读输入框 都填不进去，见下面的坑

    坑

    往只读输入框里 fill，等到超时才报错。 个人中心的用户名框带 readonly 属性，fill 会先等它「可编辑」，等不到就反复重试，直到超时（把超时设成 2 秒实测，截取开头几行）：

    Locator.fill: Timeout 2000ms exceeded.
Call log:
  - waiting for get_by_label("用户名")
    - locator resolved to <input readonly id="username-ro" data-testid="username-ro"/>
    - fill("bob")
  - attempting fill action
    2 × waiting for element to be visible, enabled and editable
      - element is not editable

    第一行只说超时，原因藏在 Call log 里的 element is not editable；默认超时 30 秒，一条用例白等半分钟。验证「这个框不让改」用断言 expect(locator).not_to_be_editable()，读值用 input_value()。

    10.2 选择类控件¶

    10.2.1 下拉框 select_option¶

    练习场的城市下拉框，三种选法：

    city = page.get_by_label("城市")

city.select_option(label="杭州")            # 按选项显示的文字选
print(city.input_value())                   # hz
city.select_option("bj")                    # 按选项的 value 选（一个参数时默认按 value 匹配）
print(city.input_value())                   # bj
city.select_option(index=3)                 # 按位置选，从 0 数起（0 是「请选择」）
print(city.input_value())                   # hz
print(city.locator("option:checked").inner_text())   # 杭州：读当前选中项显示的文字

    日常用 label=（看得懂）或 value（文案常改时更稳）。index 依赖选项顺序，选项一加就错位，少用。订单页按状态筛选就是它：

    page.get_by_label("状态").select_option(label="已取消")

    select_option 只对 <select> 元素有效。页面上那些用 div 画出来的「假下拉框」，得按普通元素点击处理：点开下拉、点中选项，各写一步 click()。

    10.2.2 复选框 check / uncheck / set_checked¶

    agree = page.get_by_label("同意协议")
print(agree.is_checked())          # False
agree.check()
print(agree.is_checked())          # True
agree.uncheck()
print(agree.is_checked())          # False
agree.set_checked(True)            # 直接指定勾上还是取消
print(agree.is_checked())          # True

    check() 有个贴心之处：先检查目标状态，已经是勾选的就什么都不做。断言勾选状态用 expect(agree).to_be_checked()，用法和第 8 章 8.7 节的其他断言一样。

    10.2.3 单选按钮：只能换选，不能取消¶

    微信、支付宝两个单选按钮是一组（name 都是 pay），选一个，另一个自动弹开：

    wx, alipay = page.get_by_label("微信"), page.get_by_label("支付宝")
wx.check()
print(wx.is_checked(), alipay.is_checked())     # True False
alipay.check()
print(wx.is_checked(), alipay.is_checked())     # False True

    对单选按钮调 uncheck() 会直接报错：

    Locator.uncheck: Error: Cannot uncheck radio button.
Radio buttons can only be unchecked by selecting another radio button in the same group.

    单选组没有「全不选」的状态，要换选就选另一个。已经选中的再 check() 一次没有副作用，测试代码里可以放心地先把要的点一遍。

    10.2.4 日期与时间输入框¶

    日期输入框（type="date"）看着像三个下拉，本质是一个输入框，值有固定格式，用 fill 填：

    day = page.get_by_label("日期")
day.fill("2026-10-22")
print(day.input_value())     # 2026-10-22
day.fill("2026/10/22")

    Locator.fill: Error: Malformed value

    必须用 ISO 格式：日期 年-月-日，时间 时:分，日期时间 年-月-日T时:分。写成斜杠分隔直接报 Malformed value——错在用例里，总好过错在线上。时间类的两个输入框同理：

    page.locator("#t").fill("09:30")                    # type="time"
page.locator("#dt").fill("2026-10-22T09:30")        # type="datetime-local"

    10.3 鼠标类¶

    10.3.1 click 的参数：哪个键、点几下¶

    click() 两个常用参数：button 选左中右键，click_count 设连点次数。双击有现成的 dblclick()；右键就是 button="right"：

    page.get_by_test_id("btn-dblclick").dblclick()      # 双击，计数加 1
page.get_by_test_id("canvas").click(button="right")  # 右键点方框

    练习场对这两处都有反应：双击计数变成 1，右键结果显示坐标。再看两个容易想错的写法：

    count = page.get_by_test_id("dblcount")
page.get_by_test_id("btn-dblclick").dblclick()
page.get_by_test_id("btn-dblclick").dblclick()
print(count.inner_text())                            # 2
page.get_by_test_id("btn-dblclick").click()          # 两次分开的 click
page.get_by_test_id("btn-dblclick").click()
print(count.inner_text())                            # 还是 2：两次单击凑不成双击
page.get_by_test_id("btn-dblclick").click(click_count=2)
print(count.inner_text())                            # 3：click_count=2 等价于 dblclick

    浏览器判断双击，看的是鼠标事件里带的「这是第几下」计数。每次 click() 发出的都是「第 1 下」，所以连着两次 click() 永远凑不成双击；click(click_count=2) 会依次发出第 1 下和第 2 下，效果就和 dblclick() 一样。要测双击行为，用这两个之一。右键点击还能用 position 指定点在元素内的位置：

    page.get_by_test_id("canvas").click(button="right", position={"x": 10, "y": 10})
print(page.get_by_test_id("context-result").inner_text())   # 右键点了方框（10, 10）

    10.3.2 hover：悬停¶

    悬停触发的菜单、提示，用 hover()。练习场的「把鼠标放上来」按钮，悬停后右边出现提示，移开就消失：

    tip = page.get_by_test_id("tip")
expect(tip).to_be_hidden()
page.get_by_test_id("btn-hover").hover()
expect(tip).to_be_visible()
page.mouse.move(10, 10)              # 把鼠标挪走
expect(tip).to_be_hidden()

    悬停触发的元素是「过了这村没这店」的：鼠标一挪走就没了，断言要紧跟在 hover() 后面。

    10.3.3 拖动：三步曲¶

    练习场的「拖我」方块用原生鼠标事件实现拖动，对应 Playwright 的鼠标三步：按下、移动、松开（先 move 到方块上）：

    box = page.get_by_test_id("box")
bb = box.bounding_box()                       # 方块的位置和尺寸
page.mouse.move(bb["x"] + 30, bb["y"] + 30)   # 移到方块中间
page.mouse.down()                             # 按下
page.mouse.move(bb["x"] + 130, bb["y"] + 80, steps=5)   # 分 5 小步移过去
page.mouse.up()                               # 松开
print(page.get_by_test_id("pos").inner_text())   # (260px, 568px)，页面记录的落点，随窗口大小略有不同

    steps=5 让移动拆成 5 小步，沿途触发 5 次 mousemove。练习场的方块只认最后的位置，把 steps 去掉一步移过去，实测落点同样是 (260px, 568px)；但有些拖拽组件（比如设了移动阈值的列表排序）要看到连续的 mousemove 才认定「开始拖了」，一步跳过去会拖不动，遇到时加上 steps。bounding_box() 返回元素左上角坐标和宽高，拖动、画布点选都靠它定位。

    常见场景「把 A 拖到 B」有一个便捷封装 drag_to：

    box.drag_to(page.get_by_role("heading", name="交互练习场"), target_position={"x": 100, "y": 10})
print(page.get_by_test_id("pos").inner_text())   # (230px, 51px)

    它内部就是三步曲。HTML5 拖拽接口（draggable="true"）实现的拖放走的不是鼠标事件，drag_to 可能无效，遇到时再查文档。

    10.3.4 滚动¶

    绝大多数时候不用管滚动：click()、fill() 这类操作执行前会自动把元素滚进可视区。需要主动滚的场景有两种。

    一是把某个元素滚到眼前（比如截图、肉眼核对）：

    page.get_by_test_id("btn-submit").scroll_into_view_if_needed()

    二是模拟滚轮（测试吸顶菜单、懒加载这类「滚动才触发」的行为）：

    page.mouse.move(400, 200)      # 滚轮作用在鼠标所在位置
page.mouse.wheel(0, 600)       # 向下滚 600；向上用负数

    两个要点。第一，滚轮异步生效，wheel() 返回时页面还没滚到位，断言交给会重试的 expect，比如 expect(元素).to_be_in_viewport()；第二，窗口放得下整页时没有可滚的空间，wheel 是空操作。用一个 800×400 的小窗口实测：

    page = browser.new_page(viewport={"width": 800, "height": 400})
page.goto("/lab.html")
print(page.evaluate("document.documentElement.scrollHeight"))   # 1025：页面比窗口高，有得滚
page.get_by_test_id("btn-submit").scroll_into_view_if_needed()
print(page.evaluate("window.scrollY"))                          # 594：滚到了提交按钮
page.mouse.move(400, 200)
page.mouse.wheel(0, -600)
print(page.evaluate("window.scrollY"))                          # 594：滚轮还没生效
expect(page.get_by_role("heading", name="交互练习场")).to_be_in_viewport()   # 等到标题回到视野里

    scroll_into_view_if_needed 返回时已经滚到位，读 scrollY 立刻是新值；wheel 之后马上读还是旧值，换成 expect 断言才稳。

    坑

    页面不比窗口高，滚动用例等于没测。 实测商品页在默认 1280×720 的窗口里 scrollHeight 正好是 720，一屏放得下，wheel(0, 600) 之后 scrollY 还是 0。「滚动后吸顶」「滚到底加载更多」这类断言在这种页面上会白白通过或白白失败。测滚动行为前先打印 scrollHeight 和窗口高度确认有得滚，必要时用 viewport 参数把窗口调小，或者用 @pytest.mark.browser_context_args(viewport={...}) 只对这一条用例生效。

    10.4 浏览器自带弹窗：dialog 事件¶

    alert、confirm、prompt 是浏览器画的弹窗，不是页面元素，定位器找不到。Playwright 的处理方式是事件：提前注册一个处理函数，弹窗一出现就调用它。练习场的三个按钮各对应一种：

    # alert：只有确定，读文字即可
page.once("dialog", lambda d: (print(d.type, d.message), d.accept()))
page.get_by_test_id("btn-alert").click()
# 打印：alert 已保存

# confirm：accept 是确定，dismiss 是取消，页面把选择写进 result
result = page.get_by_test_id("result")
page.once("dialog", lambda d: d.accept())
page.get_by_test_id("btn-confirm").click()
print(result.inner_text())       # 你点了确定
page.once("dialog", lambda d: d.dismiss())
page.get_by_test_id("btn-confirm").click()
print(result.inner_text())       # 你点了取消

# prompt：accept 可以带输入的文字
page.once("dialog", lambda d: d.accept("小麦"))
page.get_by_test_id("btn-prompt").click()
print(result.inner_text())       # 你输入了：小麦

    处理函数里的 d 是 Dialog 对象：d.type 是弹窗类型（alert / confirm / prompt），d.message 是弹窗文字，要断言「弹的是什么」就把它们存进变量再 expect。

    page.once 只处理下一个弹窗，page.on 处理之后所有的弹窗，还会收到的用 page.remove_listener 摘掉：

    def on_dialog(d):
    print(d.type, d.message)
    d.accept()

page.on("dialog", on_dialog)     # 这之后每个弹窗都自动点确定
page.remove_listener("dialog", on_dialog)

    坑

    不注册处理函数，弹窗被自动「取消」。 Playwright 的默认行为是自动关掉弹窗，相当于点了取消。实测不注册任何处理函数直接点「弹确认框」，用例不报错，页面上写的是「你点了取消」。「点了按钮没反应」的用例，先想想是不是有个 confirm 被静默关掉了。

    坑

    注册了处理函数却忘了 accept 或 dismiss。 处理函数里只是打印、两个方法都不调，弹窗就一直开着，Playwright 等「这个弹窗处理完」才执行后面的代码，操作会等到超时。处理函数的最后一行一定是 accept 或 dismiss。

    页面自己画的弹窗（比如商品页的购买弹窗）就是普通元素，page.get_by_role("dialog") 定位即可，两者别混。

    10.5 文件上传与下载¶

    10.5.1 上传：set_input_files¶

    个人中心有头像上传：<input type="file"> 加一个「上传头像」按钮。自动化里不去点文件选择窗口——那是操作系统的东西，Playwright 碰不到——直接把文件塞给输入框：

    page.goto("/profile.html")
page.get_by_test_id("avatar-file").set_input_files("data/avatar.png")
page.get_by_test_id("avatar-upload").click()
expect(page.get_by_test_id("avatar-msg")).to_contain_text("上传成功")

    测试用图不必真找一张，PNG 的字节结构是固定的，十几行代码就能现造一个 1×1 的：

    import struct, zlib

def tiny_png_bytes() -> bytes:
    def chunk(tag, data):
        return struct.pack(">I", len(data)) + tag + data + struct.pack(">I", zlib.crc32(tag + data) & 0xFFFFFFFF)
    png = b"\x89PNG\r\n\x1a\n"
    png += chunk(b"IHDR", struct.pack(">IIBBBBB", 1, 1, 8, 6, 0, 0, 0))
    png += chunk(b"IDAT", zlib.compress(b"\x00\xff\x00\x00\xff"))
    png += chunk(b"IEND", b"")
    return png

    配合内存方式连临时文件都省了，直接给文件名、类型、字节：

    page.get_by_test_id("avatar-file").set_input_files(
    files=[{"name": "avatar.png", "mimeType": "image/png", "buffer": tiny_png_bytes()}]
)

    接口的校验逻辑也顺带测了。传个不支持格式（页面 accept 只写了 jpg 和 png）：

    page.get_by_test_id("avatar-file").set_input_files(
    files=[{"name": "avatar.gif", "mimeType": "image/gif", "buffer": b"GIF89a" + b"\x00" * 20}]
)
page.get_by_test_id("avatar-upload").click()
expect(page.get_by_test_id("avatar-msg")).to_have_text("上传失败：头像只支持 jpg 或 png 格式")

    一个输入框选多个文件时传列表即可：set_input_files(["a.png", "b.png"])。输入框上的 accept=".jpg,.jpeg,.png" 只是文件选择窗口的过滤提示，拦不住 set_input_files——这正好，能把非法格式塞进去测服务端的校验。个别页面点按钮后才弹系统文件选择窗口（input 藏起来了），用 page.expect_file_chooser() 等到选择器再 set_files，思路相同。

    10.5.2 下载：expect_download¶

    订单页的「导出 CSV」按钮点击后浏览器开始下载。和弹窗一样是「先注册、后触发」：with 块里的动作触发下载，出块时下载对象已经拿到：

    with page.expect_download() as download_info:
    page.get_by_test_id("export").click()
download = download_info.value

print(download.suggested_filename)    # orders.csv：从响应头 Content-Disposition 里解析的文件名
target = tmp_path / download.suggested_filename    # tmp_path 是 pytest 的临时目录夹具
download.save_as(str(target))          # 存到指定位置

    下载的文件内容可以直接读出来断言，这比只断言「文件存在」有用得多：

    content = target.read_text(encoding="utf-8-sig")
assert content.splitlines()[0] == "订单号,商品,金额(元),状态,下单时间"
assert order_no in content               # 刚造的订单在导出结果里

    坑

    CSV 打开乱码，先查编码。 这个接口返回的 CSV 带字节顺序标记（BOM，文件头三个字节 b"\xef\xbb\xbf"），用 utf-8 直接解码会读出一个看不见的首字符，得用 utf-8-sig。断言第一列对不上时，先打印 repr 看第一个字符是不是 ﻿。

    坑

    expect_download 写在点击后面。 下载事件在 expect 之前就发生了，会一直等不到。expect_xxx 系列（弹窗、下载、新标签页、接口响应）都是这个结构：with 先立好，动作写在块里。

    另外两点备忘：download.failure() 返回 None 才是下载成功；下载文件先落在 Playwright 的临时目录，浏览器一关就清掉，要留存就 save_as 到工程目录（别提交进 git）。

    10.6 新标签页¶

    点开新标签页后，原来的 page 还停在旧页面，新页面要单独拿。练习场的「点我打开新标签页」链接，结构还是「先注册、后触发」，只是这次注册在上下文上：

    with context.expect_page() as new_page_info:
    page.get_by_test_id("open-tab").click()
child = new_page_info.value          # 新标签页的 Page 对象
child.wait_for_load_state()          # 等新页面加载完

expect(child).to_have_title("子页面 - 迷你商城")
expect(child.get_by_test_id("from")).to_have_text("link")     # 新页面上照常定位、断言
print(child.url)                     # http://127.0.0.1:8000/lab-child.html?from=link

    child 是标准的 Page 对象，第 8 章的所有定位、操作、断言在它上面都成立。操作完关掉它：

    child.close()
print(len(context.pages))            # 1：上下文里又只剩原来那页

    等价写法 page.expect_popup() 注册在页面上，多数场景两者通用。页面用 window.open 自己开新窗、没有可点的链接时，用 expect_popup 更贴切。

    10.7 iframe¶

    iframe 是页面里嵌的另一个完整页面，支付页、富文本编辑器、第三方组件常用。iframe 里的元素和外层页面隔着一层，普通定位器穿不进去，要先用 frame_locator 进入：

    frame = page.frame_locator("#inner")          # 先用 CSS 找到 iframe 本身
expect(frame.get_by_test_id("from")).to_have_text("frame")   # 然后照常定位里面的元素
print(frame.get_by_test_id("query").inner_text())   # ?from=frame

    进去之后 get_by_role、get_by_label、filter 全都可用，写法和普通页面完全一样。两条等价的路子，按手头的定位器顺手选：

    page.get_by_test_id("inner-frame").content_frame.get_by_test_id("from")   # 先定位 iframe 元素，再进它的 frame
page.frame_locator("#inner").owner                                        # 反过来，从 frame 拿 iframe 元素

    iframe 有名字或地址特征时还能直接按条件取 Frame 对象：

    fr = page.frame(url=re.compile(r"from=frame"))
print(fr.get_by_test_id("from").inner_text())    # frame

    坑

    忘了进 iframe，定位一直超时。 iframe 里的元素用普通 page.get_by_test_id(...) 定位，命中 0 个，操作会等到超时，报错里只有「waiting for ...」，不提 iframe 三个字。排查「看得见却定位不到」的元素时，先在开发者工具 Elements 面板看它有没有 iframe 祖先，有就套上 frame_locator。

    10.8 综合演练：一条完整的表单用例¶

    把练习场下半页当成一张完整的表单：选城市、勾协议、选支付方式、填日期、提交、断言结果。写成正式用例，放进 tests/ui/test_action_lab.py：

    def test_lab_form_flow(page: Page):
    """综合演练：把练习场当成一张完整表单，填完提交并断言结果。"""
    page.goto("/lab.html")
    page.get_by_label("城市").select_option(label="上海")
    page.get_by_label("同意协议").check()
    page.get_by_label("支付宝").check()
    page.get_by_label("日期").fill("2026-10-22")
    page.get_by_test_id("btn-submit").click()
    expect(page.get_by_test_id("form-result")).to_have_text("城市：sh，支付方式：alipay，日期：2026-10-22")


def test_lab_form_blocked_without_agree(page: Page):
    """不勾协议点提交，页面提示要先同意协议，其他选择原样保留。"""
    page.goto("/lab.html")
    page.get_by_label("城市").select_option(label="上海")
    page.get_by_label("支付宝").check()
    page.get_by_test_id("btn-submit").click()
    expect(page.get_by_test_id("form-result")).to_have_text("要先同意协议")

    五类控件五种操作，每步都是本章讲过的写法；第二条验证校验逻辑。-k form 只挑名字里带 form 的用例：

    10.9 还有一批不常用的操作¶

    剪贴板读写、浏览器权限（摄像头、通知）、地理定位模拟、打印成 PDF 这些操作 Playwright 都支持，日常 UI 回归用得少，用到时查官方文档的 Page / BrowserContext 章节（链接见附录）。思路和本章一致：能力都挂在 page、context、locator 三类对象上，想清楚动作归谁管，再去对应对象的文档里找方法。

    10.10 常见的坑¶

    坑

    浏览器弹窗没处理，用例却通过了。 Playwright 默认自动取消弹窗（10.4 节），confirm 弹窗被静默关掉，业务动作没发生，页面没有任何异常。「点了没反应」先查 dialog。

    坑

    fill 填完联想不出现。 fill 不产生键盘事件，靠 keydown/keyup 工作的搜索联想、输入校验都没反应。换 press_sequentially，必要时加 delay。

    坑

    日期填了斜杠格式。 日期输入框只认 ISO 格式，2026/10/22 直接报 Malformed value；时间、日期时间各有各的格式（10.2.4 节）。

    坑

    对单选按钮 uncheck。 单选组只能换选、不能清空，uncheck() 直接报错。要「全不选」的场景，先和产品确认这个状态到底存不存在。

    坑

    expect_download 写在点击后面。 expect_xxx 系列必须用 with 包住触发动作，顺序反了就永远等不到事件（10.5.2 节）。

    坑

    下载的 CSV 断言第一列对不上。 文件带 BOM，utf-8 解码多出 ﻿，用 utf-8-sig 读（10.5.2 节）。

    坑

    页面一屏放得下，滚动用例白跑。 商品页在默认 1280×720 的窗口里不用滚，滚轮是空操作；滚轮本身又是异步生效的。测滚动先确认 scrollHeight 比窗口高，断言交给 expect（10.3.4 节）。

    坑

    iframe 里的元素定位超时。 普通定位器穿不进 iframe，报错只说 waiting for。先看元素有没有 iframe 祖先，有就套 frame_locator（10.7 节）。

    10.11 练习¶

    1. 在练习场上把 fill 和 press_sequentially 在键盘输入框的效果各跑一遍，再试试 fill("") 和 clear()，确认它们等价。
    2. 写一条用例：只勾协议、其他都不选直接提交，断言 form-result 是「城市：没选，支付方式：没选，日期：没选」。
    3. 用 10.5.1 的 tiny_png_bytes 造一张超过 200 KB 的「图片」（字节后面补零即可）传头像，断言页面提示「头像不能超过 200 KB」。
    4. 在订单页导出 CSV 后，断言文件里有一张用接口造好的订单号，并且状态列是「待支付」。
    5. 把 test_lab_form_flow 里的 check() 换成 click() 再跑一遍，确认也能过；想想复选框到底该用哪个，为什么页面对象方法里推荐 check()。

    10.12 自检清单¶

    • 能说出 fill、press_sequentially、press 各适合什么场景；
    • 知道日期输入框只认什么格式，time 和 datetime-local 的格式写法；
    • 会用 select_option 的三种选法，知道 index 为什么少用；
    • 能写出鼠标拖动的三步曲，知道 steps 参数干什么用；
    • 能背出浏览器弹窗的三条：默认自动取消、处理函数要 accept/dismiss、once 与 on 的区别；
    • 会现造一个 1×1 的 PNG 上传，会读下载文件的内容做断言；
    • 会处理新标签页和 iframe，知道 iframe 定位超时该怎么排查；
    • 能独立写出「填完整张表单并断言结果」的用例。
