    从零开始学 UI 自动化、接口自动化与性能测试¶

    这是一份给零基础同学的动手教程。你不需要会编程，也不需要懂自动化，只要会用电脑、会打字，跟着做就能从一个空文件夹开始，搭出一套能日常使用的自动化测试工程：

    • 接口自动化：几十条接口用例 3 秒跑完，自动检查返回结果、余额、库存对不对；
    • UI 自动化：脚本自己打开浏览器、点按钮、填表单，检查页面显示，失败了自动截图、留下操作录像；
    • 性能测试：模拟大量用户同时访问，找出系统最多能承受多大的访问量、瓶颈在哪里；
    • 工程化：一条命令跑完全部用例、生成图文报告，接进流水线每天自动跑。

    教程里的工程代码和命令都在 2026 年 10 月实际跑通过，正文里的运行结果、压测数字都是实测出来的，版本见文末。少数需要外部环境的示例（数据库断言、流水线配置、群机器人通知）会在正文里注明「只演示写法」。

    下载参考代码

    点击下载 autotest-demo.zip：学完全部章节后的完整工程，包括练习网站。 解压后就是 autotest-demo 文件夹，正文里提到的「参考代码」就是它。

    为什么先学接口、再学 UI、最后学性能？

    • 接口自动化性价比最高。 大部分功能问题在接口层就能发现，不用等页面做完；一条接口用例几十毫秒就能跑完；接口比页面稳定，页面一改版 UI 脚本就要跟着改，接口用例基本不用动。业内常说的测试金字塔就是这个意思：底层的接口用例写得最多，顶层的 UI 用例只覆盖最关键的几条流程。
    • UI 自动化建立在接口之上。 学完接口自动化再学 UI，你会用接口准备测试数据、用接口核对后台结果，UI 脚本只负责页面上的操作和展示，这样写出来的 UI 用例又快又稳。
    • 性能测试要用到前两块的知识。 压测脚本本质上是「很多个用户同时调接口」，关联、参数化、断言这些概念在接口自动化里都学过了。

    二、用到的工具¶

    用途 选用 为什么选它 其他常见选择
    编程语言 Python 3.13 语法简单，测试圈用得最多，三块内容用同一门语言 Java、JavaScript
    发送接口请求 requests 最经典的 HTTP 库，资料最多 httpx
    组织和运行用例 pytest Python 测试框架的事实标准，夹具、参数化、插件都很强 unittest
    UI 自动化 Playwright 自动等待元素就绪，脚本更稳；自带录制、录像回放；新项目的主流选择 Selenium（第 12 章专门对照）
    性能测试 LoadRunner（社区版） 企业里用得最多的商业压测工具，脚本、场景、监控、分析报告一套齐全；社区版免费，50 个虚拟用户 JMeter、Locust、k6
    测试报告 Allure 3 图文并茂，能看到每一步的请求、响应和截图 pytest-html
    持续集成 GitHub Actions / Jenkins 推代码或定时自动跑 GitLab CI

    JMeter 在国内公司里用得也很多，第 18 章末尾有一张 LoadRunner 与 JMeter、Locust 的概念对照表，学会了一个，再上手另外两个会很快。

    四、怎么用这份教程¶

    1. 一定要动手敲。 每一段代码都自己敲一遍、运行一遍，看到结果再往下读。只看不敲，第二天就忘了。
    2. 每章的结构都一样：本章目标 → 动手做 → 讲原理 → 常见的坑 → 练习 → 自检清单。自检清单的问题都能答上来，再进下一章。
    3. 报错了别慌。 先读报错的最后几行，大多数时候它已经告诉你哪里错了；怎么读报错、怎么分清是哪一类错误，见第 1 章 1.6.14 节。再去 附录 查常见报错；还不行就把报错原文复制到搜索引擎或 AI 助手里问。
    4. 参考代码在 autotest-demo.zip 里（点击下载，解压后就是 autotest-demo 目录），是学完全部章节后的最终版本。正文里会先给出简单的写法，再一步步改进，所以你写到一半的代码和参考代码长得不一样是正常的。卡住了再去对照，别一上来就复制。
    5. 练习网站是现成的（autotest-demo/shop/ 目录），复制过去就能用，不需要看懂它的代码。
    6. 按自己的起点选读法。
      • 没学过 Python，或者学过但忘光了：把第 1 章 1.6 节的例子一个一个敲一遍，1.9 节的自检清单都能答上来再往下。第 3 章起每段代码都会用到这些语法，读到看不懂的写法就翻回 1.6 节对应的小节，运行报错先按 1.6.14 节分清是哪一类；
      • 只想先学性能测试：做完第 1 章 1.1～1.5 节（装环境）和第 2 章（跑起练习网站），就可以直接读第 13～18 章。LoadRunner 的脚本是 C 语言的写法，和 Python 关系不大。中间几处用 Python 核对数据的地方，用的是第 4 章写的接口客户端，把参考工程里的 common 文件夹复制到自己的工程里就能运行；第 18 章 18.4.7 节的 pytest 用例，等学完接口自动化再回来做；
      • 第 19 章要用到前面所有的内容，放到最后读。

    五、约定¶

    • 教程以 Windows 为例，命令在 PowerShell 里执行（VS Code 的终端默认就是 PowerShell）。Mac 和 Linux 上大部分命令一样，有区别的地方会单独说明。
    • 代码块里以 > 开头的行表示要在命令行输入的命令，> 本身不用输入；没有 > 的是程序输出或文件内容。
    • 文件路径都相对于工程根目录 autotest-demo，比如 tests/api/test_login.py。
    • 教程里有些地方要设置环境变量，PowerShell 写法是 $env:名字 = "值"。它只对当前这个命令行窗口有效，并且一直有效到窗口关闭，用完要去掉：Remove-Item Env:名字，或者直接关掉窗口重开。忘了去掉，后面的实验结果就会莫名其妙。
