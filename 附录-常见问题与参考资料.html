    附录 常见问题与参考资料¶

    A. 常见报错速查¶

    遇到报错，先读最后几行，再到这里按关键字查。

    环境与安装¶

    现象或报错 原因与解决
    python 不是内部或外部命令 安装 Python 时没勾 Add python.exe to PATH，重新安装勾上
    装好了 Node.js 或 Git，VS Code 的终端里还是「不是内部或外部命令」 VS Code 的终端用的是 VS Code 启动时的环境，要把 VS Code 整个关掉重开；单独的 PowerShell 窗口新开一个即可
    输入 python 打开了微软应用商店 「设置 → 应用 → 高级应用设置 → 应用执行别名」里关掉 python.exe 和 python3.exe
    无法加载文件 ...\Activate.ps1，因为在此系统上禁止运行脚本 执行 Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
    pip 下载很慢、超时 换镜像源：pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple；公司网络要走代理的，加 --proxy http://代理地址:端口
    装 locust 时报错，提到 gevent、编译、C++ Python 版本太新，对应的安装包还没发布，换成 Python 3.13 或 3.14
    ModuleNotFoundError: No module named 'xxx' 虚拟环境没激活（命令行开头没有 (.venv)），或者包没装
    命令行里中文显示成乱码 先执行 $env:PYTHONUTF8 = "1"，让 Python 统一用 UTF-8 输出；用 Windows 终端或 VS Code 自带的终端也能减少乱码
    读文件报 UnicodeDecodeError 打开文件时加 encoding="utf-8"
    git status 里中文文件名显示成 \346\265\213 这样 执行 git config --global core.quotepath false
    git commit 报 Author identity unknown 没设置名字和邮箱，执行 git config --global user.name "你的名字" 和 git config --global user.email "你的邮箱"
    git push 报 src refspec main does not match any 本地分支叫 master，先执行 git branch -M main

    练习网站¶

    现象或报错 原因与解决
    [Errno 10048] error while attempting to bind on address ('127.0.0.1', 8000) 8000 端口被占了，多半是已经开着一个练习网站。关掉那个窗口，或者用 --port 8001
    用例报 Connection refused、Max retries exceeded 练习网站没启动，或者启动它的窗口被关了
    No module named 'shop' 没在工程根目录执行启动命令
    接口文档页 /docs 白屏 页面资源要从国外的公共资源站加载，网络不通。看第 2 章的接口表，或者打开 /openapi.json
    数据被弄乱了 重启练习网站，所有数据恢复初始状态
    设置了开关（环境变量）不生效 环境变量只对设置它的那个命令行窗口有效，并且要重启练习网站
    做完开关实验（第 6 章的 token 过期、越权，性能章的连接池、单会话），用例莫名失败、数字和书上差很多 开关还开着。环境变量一直有效到窗口关闭，用 Get-ChildItem Env:SHOP*、Get-ChildItem Env:STEP* 看看还剩哪些，用 Remove-Item Env:名字 去掉（或者关掉窗口重开），再重启练习网站
    跑用例时全都连到了一个不存在的地址 当前窗口里还留着 TEST_ENV，执行 Remove-Item Env:TEST_ENV
    用例成片报 401、业务码 40102「登录已过期」 练习网站是带 SHOP_TOKEN_TTL 启动的，token 几秒就过期。去掉这个环境变量重启网站（第 6 章 6.4 节）
    上传头像的接口一调用网站就报错，或者网站起不来，提到 python-multipart 依赖没装全，执行 pip install -r requirements.txt

    接口自动化¶

    现象或报错 原因与解决
    collected 0 items 文件名、函数名没以 test_ 开头，或者不在 testpaths 指定的目录里
    ModuleNotFoundError: No module named 'common' pytest.ini 里没写 pythonpath = .，或者 common 里没有 __init__.py
    fixture 'xxx' not found 夹具名拼错，或者 conftest.py 不在用例所在目录或它的上级目录
    import file mismatch 不同目录下有同名的用例文件，改个名字
    返回 422，参数看着没问题 把 json= 写成了 data=
    跑完某条用例后，后面全部 401 那条用例让共享的 token 失效了（比如退出登录），改用专用账号
    单独跑能过，一起跑或并行跑就失败 用例之间共用了数据：账号余额、商品库存。见第 4 章 4.8 节、第 19 章 19.3 节
    小数比较偶尔失败 用 pytest.approx
    -k 中文 选不到用例 用例编号里的中文被转义了，在 pytest.ini 里加 disable_test_id_escaping_and_forfeit_all_rights_to_community_support = true

    UI 自动化¶

    现象或报错 原因与解决
    Executable doesn't exist ... Please run the following command to download new browsers 加 --browser-channel=chrome 用本机的 Chrome，或者执行 playwright install chromium
    strict mode violation: ... resolved to 10 elements 定位到了多个元素，用 filter(has_text=...) 缩小范围
    Timeout 30000ms exceeded 元素一直没出现。用 --headed 看着跑，或者打开 trace.zip 看当时的页面
    有时过有时不过 用了 sleep、count()、is_visible() 做断言，换成 expect；或者数据被别的用例改了
    种了 cookie 还是被带回登录页 页面还依赖别的 cookie 或本地存储，先手工登录一次，在开发者工具里看全
    点了按钮没反应、也不报错 浏览器确认框被自动关掉了，提前用 page.once("dialog", ...) 处理
    test-results 里的东西不见了 每次运行开始会清空，要留存就跑完拷走或挂进报告
    fill 之后页面上监听按键的提示没出现 fill 一次性写入，不触发逐个按键的事件，改用 press_sequentially（第 10 章 10.1 节）
    Selenium 报 NoSuchDriverException: Unable to obtain driver for chrome Selenium 下载不了 chromedriver，按第 12 章 12.2.2 节手动下载，Service() 指定路径
    Selenium 报 session not created，提到 Chrome version Chrome 升级了，chromedriver 版本没跟上，下载同版本的覆盖
    Selenium 报 StaleElementReferenceException 拿到的元素在页面刷新后作废了，重新 find_element，别缓存元素对象
    Selenium 报 UnexpectedAlertPresentException 有个浏览器弹窗没处理，先 ec.alert_is_present() 等它出现再 accept 或 dismiss
    Selenium 用例并行跑时偶尔失败，单独跑却都过 实测并行时会偶发输入、点击没生效，和其他用例分开、串行跑（第 19 章 19.3.2 节）

    性能测试¶

    现象或报错 原因与解决
    网页界面打不开，提示 8089 端口被占用 已经开着一个 Locust，关掉它，或者加 --web-port 8090
    --processes 不能用 这个参数不支持 Windows，改用 --master 加 --worker（第 8 章 8.6 节）
    CPU usage above 90%! This may constrain your throughput... 压测机的 CPU 不够了，测出来的数字不准，用多个工作进程
    统计表里同一个接口有几十行 动态地址没用 name= 分组
    大量 401 所有虚拟用户共用一个账号被互相顶掉，用账号池
    结束时打印 ValueError: I/O operation on closed file Locust 2.47 写 CSV 的后台任务没来得及停，不影响结果和退出码
    CSV 里的请求总数比控制台少一点 CSV 每隔一两秒写一次，最后一两秒没写进去，最终数字以控制台和 HTML 报告为准
    压测结果每次差很多 压测机和服务器在同一台电脑上抢资源、有别人同时在用环境、数据量不一样
    长时间压测后支付大量失败，报余额不足 测试数据耗尽了。压测前按时长算够余额，练习网站用 SHOP_INIT_BALANCE 调大初始余额（第 8 章 8.7 节）

    报告¶

    现象或报错 原因与解决
    allure 不是内部或外部命令 没装 Node.js 或 Allure，或者装完没有新开命令行窗口
    allure generate 执行完什么都没打印 正常，它成功时不输出，去 reports/allure-report 找 index.html
    双击报告是空白页 多文件报告不能直接双击，用 allure open reports/allure-report，或者在 allurerc.yaml 里开 singleFile: true
    报告里新旧结果混在一起 跑用例时加 --clean-alluredir
    网上教程让装 allure-commandline 那是需要 Java 的 Allure 2，本教程用的是 Allure 3，包名叫 allure

    B. 术语表¶

    中文 英文 一句话解释
    用例 test case 一个检查点：在什么条件下、做什么操作、期望什么结果
    断言 assertion 检查实际结果是否等于期望结果的那句代码
    夹具 fixture pytest 里负责准备数据、清理数据的函数
    参数化 parametrize 同一份用例代码，用多组数据各跑一遍
    数据驱动 data-driven 测试数据放进文件里，代码只负责读数据、执行、断言
    接口串联 chaining / correlation 前一个接口的返回值作为后一个接口的输入
    契约 contract / schema 接口返回结构的约定：有哪些字段、什么类型
    模拟服务 mock 代替真实依赖的假服务，按约定返回固定结果
    等价类 equivalence class 一组处理方式相同的输入，挑一个代表测就够了
    边界值 boundary value 规则的分界点和它两侧的值，缺陷最爱藏的地方
    判定表 decision table 把条件的所有组合列成表，每种组合对应一个期望结果
    状态迁移 state transition 按「什么状态下做什么操作、变成什么状态」设计用例
    签名 signature 用密钥对请求内容算出的校验串，防篡改、防重放
    刷新令牌 refresh token 专门用来换新 token 的长期凭证，一次性使用
    水平越权 IDOR 用自己的合法身份操作了别人的数据
    轮询 polling 每隔一段时间查一次结果，直到完成或超时
    工厂夹具 factory fixture 返回一个造数函数的夹具，一条用例里可以造多份数据
    页面对象 page object 把一个页面的元素和操作封装成一个类
    定位器 locator 描述「怎么在页面上找到某个元素」的对象
    无界面模式 headless 浏览器在后台运行，不显示窗口
    显式等待 explicit wait Selenium 里指定条件的等待，条件满足就继续，超时报错
    浏览器驱动 chromedriver Selenium 用来操纵 Chrome 的中间程序，版本要和浏览器一致
    操作录像 trace Playwright 记录的每一步操作、页面快照和网络请求
    不稳定用例 flaky test 代码没变，有时通过有时失败的用例
    冒烟测试 smoke test 最核心的一小批用例，用来快速判断系统基本可用
    回归测试 regression test 改动之后把已有功能再测一遍，确认没被改坏
    虚拟用户 virtual user（Vuser） 压测工具模拟出来的一个用户
    思考时间 think time 用户两次操作之间停顿的时间
    每秒请求数 RPS / QPS 服务器每秒处理的请求数
    每秒事务数 TPS 每秒完成的业务操作数，一个事务可能包含多个请求
    分位数 percentile P95 表示 95% 的请求比它快
    吞吐量 throughput 单位时间内处理的工作量
    拐点 knee point 压力再加，吞吐量不再增长、响应时间陡增的那个点
    事务 transaction LoadRunner 里圈起来统计耗时的一段业务操作
    集合点 rendezvous 让一批虚拟用户在同一时刻一起执行下一步，用来造严格并发
    关联 correlation 把上一个响应里的动态值取出来，给后面的请求用
    负载生成器 load generator 真正发出压力的机器或进程
    服务水平协议 SLA 事先约定的性能指标，压测结果按它判定达标与否
    瓶颈 bottleneck 限制系统处理能力的那个资源
    性能门禁 performance gate 按事先定好的性能指标，自动判定达标与否
    竞态条件 race condition 多个操作同时进行时，结果取决于执行先后顺序的缺陷
    幂等 idempotency 同一个请求执行一次和执行多次，效果相同
    持续集成 CI, continuous integration 每次提交代码都自动构建、自动测试
    流水线 pipeline 一串自动执行的步骤
    退出码 exit code 程序结束时返回的数字，0 表示成功

    D. 公开的练习网站¶

    练完本教程的练习网站，想换个网站练手，下面这些是专门给测试练习用的公开网站。它们只能用来练功能自动化，不要拿来做性能测试，那相当于攻击别人的网站。

    网站 适合练什么
    The Internet（https://the-internet.herokuapp.com/） 四十多个小页面，每个页面一种难点：iframe、新窗口、上传、弹窗、拖拽、动态加载
    Sauce Demo（https://www.saucedemo.com/） 完整的购物流程；有被故意弄坏的用户（登录被锁、图片错乱、响应很慢），适合练异常场景
    Restful Booker（https://restful-booker.herokuapp.com/） 接口练习：增删改查、鉴权，里面埋了缺陷。数据每 10 分钟重置，用例要自己造数据
    DemoQA（https://demoqa.com/） 各种表单控件、弹窗、iframe、新窗口
    UI Testing Playground（http://uitestingplayground.com/） 专门练等待和时机问题：延迟加载、动态 id、会移动的按钮
    Automation Exercise（https://automationexercise.com/） 带现成测试用例清单的商城，界面和接口都能练
    Practice Software Testing（https://practicesoftwaretesting.com/） 完整的工具商城，有接口文档

    更多的网站可以看这两个合集：https://github.com/BMayhew/awesome-sites-to-test-on、https://gist.github.com/proffesor-for-testing/d0ac58084b8e37f921b8c04a20229d16。这些网站随时可能改版或下线，打不开就换一个。
