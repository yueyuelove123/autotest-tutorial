    第 12 章 Selenium 对照¶

    本章目标

    • 会安装并启动 Selenium，知道 chromedriver 和浏览器版本要配套；
    • 会用 Selenium 的八种定位方式和显式等待，写出能跑的用例；
    • 能把 Selenium 和 Playwright 的写法一一对上，看得懂公司里的存量 Selenium 代码；
    • 知道新项目该怎么在两个工具之间做选择。

    前面的章节都用 Playwright 写 UI 自动化。这一章换一个工具：Selenium，目的是让你看得懂、改得动公司里已经存在的自动化项目——国内存量的 UI 自动化代码，一大半是 Selenium 写的，招聘要求里它也是最常出现的名字。学完这一章你会发现：换的只是 API 的名字，第 8 章到第 11 章建立的所有概念（定位、等待、页面对象、接口造数）原封不动都能搬过去。

    12.1 为什么还要认识 Selenium¶

    Selenium 从 2004 年做到现在，是 UI 自动化的老前辈。它和 Playwright 的底层原理不同：

    • Selenium 走的是 W3C 的 WebDriver 协议：脚本把「点这个按钮」发给一个叫 chromedriver 的中间程序，中间程序再去操纵浏览器。浏览器、中间程序、脚本三个进程分开，什么浏览器都能接；
    • Playwright 用的是浏览器自带的调试接口，直接和浏览器对话，不用中间程序。

    这个差别带来了两者最直观的两点不同：Selenium 需要额外准备一个和浏览器版本配套的 chromedriver（12.2 节专门讲），Playwright 不需要；Selenium 找不到元素不会自动等（12.4 节专门讲），Playwright 默认会等。

    两个工具各自适合什么场合，12.7 节有一张完整的对照表。先把环境跑起来。

    12.2 安装与第一次启动¶

    12.2.1 安装¶

    在工程虚拟环境里装（照旧用钉死的版本）：

    (.venv) > pip install selenium==4.36.0

    同时把它写进 requirements.txt，和其它依赖放在一起：

    # UI 自动化（Selenium 对照章用）
selenium==4.36.0

    12.2.2 chromedriver：版本要配套¶

    Selenium 操纵 Chrome 靠的是 chromedriver，它和 Chrome 一样有自己的版本号，两者的大版本必须一致：Chrome 155 就要配 155 的 chromedriver。版本不配套时，轻则报警告，重则直接起不来。

    Selenium 自带一个叫 Selenium Manager 的小工具，webdriver.Chrome() 不带参数时会自动去下载配套的 chromedriver。可以先试它：

    from selenium import webdriver

driver = webdriver.Chrome()          # 第一次运行会自动下载 chromedriver，要等一会儿
driver.get("https://www.example.com")
print(driver.title)
driver.quit()

    下载源在国外，国内网络经常失败。失败时长这样：

    selenium.common.exceptions.NoSuchDriverException: Message: Unable to obtain driver for chrome; For documentation on this error, please visit: https://www.selenium.dev/documentation/webdriver/troubleshooting/errors/driver_location

    这时手动下载，两步：

    1. 查浏览器的版本号：Chrome 地址栏输入 chrome://version，第一行就是，比如 155.0.8059.79；
    2. 下载同版本的 chromedriver：官方清单在 https://googlechromelabs.github.io/chrome-for-testing/known-good-versions-with-downloads.json（浏览器打开搜索自己的版本号），国内镜像 https://registry.npmmirror.com/-/binary/chrome-for-testing/（进 对应版本/win64/ 下载 chromedriver-win64.zip）。解压出 chromedriver.exe，放到一个固定的地方，比如 D:\tool\chromedriver\。

    以后每个用到 Selenium 的脚本，开头都这样指定路径（原始字符串 r"..." 免去反斜杠转义的麻烦）：

    from selenium import webdriver
from selenium.webdriver.chrome.service import Service

driver = webdriver.Chrome(service=Service(r"D:\tool\chromedriver\chromedriver.exe"))

    坑

    Chrome 自动升级后 Selenium 全挂。 Chrome 默认自动更新，升完大版本，chromedriver 就对不上了，报 session not created 或 Chrome version must be ...。修法就是重新下载配套的 chromedriver 覆盖旧的。团队里建议把 Chrome 的自动更新关掉，或者把「升级浏览器要同步换 driver」写进维护文档。

    12.2.3 第一个脚本¶

    新建 scratch/selenium_basics.py（一次放全，下面 12.3 到 12.5 节逐段讲；练习网站照旧跑在 8000 端口）：

    """用 Selenium 把练习网站走一遍：登录、搜索（显式等待）、下拉筛选、弹窗、iframe、新标签页。

运行前：练习网站在 8000 端口运行着；chromedriver.exe 放在 D:/tool/chromedriver/ 下（12.2 节）。
"""
from selenium import webdriver
from selenium.webdriver.chrome.service import Service
from selenium.webdriver.common.by import By
from selenium.webdriver.support import expected_conditions as ec
from selenium.webdriver.support.ui import Select, WebDriverWait

BASE = "http://127.0.0.1:8000"

driver = webdriver.Chrome(service=Service(r"D:\tool\chromedriver\chromedriver.exe"))
wait = WebDriverWait(driver, 10)            # 显式等待：最多等 10 秒，条件满足立刻往下走

# 1. 登录
driver.get(f"{BASE}/login.html")
driver.find_element(By.ID, "username").send_keys("alice")
driver.find_element(By.ID, "password").send_keys("alice123")
driver.find_element(By.CSS_SELECTOR, "button[type=submit]").click()
wait.until(ec.url_contains("/products.html"))
print("1 登录后的页面：", driver.current_url.rsplit("/", 1)[-1])

# 2. 搜索：点完按钮立刻数行数，和等列表刷新后再数，结果不一样
box = driver.find_element(By.ID, "keyword")
box.send_keys("耳机")
driver.find_element(By.CSS_SELECTOR, "#search-form button[type=submit]").click()
print("2 点完搜索立刻数：", len(driver.find_elements(By.CSS_SELECTOR, "#rows tr")), "行")
wait.until(lambda d: len(d.find_elements(By.CSS_SELECTOR, "#rows tr")) == 2)
first = driver.find_elements(By.CSS_SELECTOR, "#rows tr")[0]
print("2 等列表刷新后再数：", len(driver.find_elements(By.CSS_SELECTOR, "#rows tr")), "行，第一行：", first.text.split(" ")[0])

# 3. 下拉框：Selenium 用 Select 类操作原生 select
driver.get(f"{BASE}/lab.html")
Select(driver.find_element(By.ID, "city")).select_by_visible_text("杭州")
print("3 下拉框选中：", Select(driver.find_element(By.ID, "city")).first_selected_option.text)

# 4. 浏览器弹窗：先等弹窗出现，再切过去点取消
driver.find_element(By.ID, "btn-confirm").click()
alert = wait.until(ec.alert_is_present())
print("4 弹窗文字：", alert.text)
alert.dismiss()
print("4 点取消后：", driver.find_element(By.ID, "result").text)

# 5. iframe：先切进去才能找里面的元素，用完切回来
driver.switch_to.frame("inner")
print("5 iframe 里的文字：", driver.find_element(By.CSS_SELECTOR, "[data-testid=from]").text)
driver.switch_to.default_content()

# 6. 新标签页：记住原窗口，等第二个窗口出现后切过去
main = driver.current_window_handle
driver.find_element(By.CSS_SELECTOR, "[data-testid=open-tab]").click()
wait.until(ec.number_of_windows_to_be(2))
driver.switch_to.window([h for h in driver.window_handles if h != main][0])
print("6 新标签页里的文字：", driver.find_element(By.CSS_SELECTOR, "[data-testid=from]").text)
driver.close()
driver.switch_to.window(main)

driver.quit()

    运行（本机实测，两轮输出一致）：

    (.venv) > python scratch\selenium_basics.py
1 登录后的页面： products.html
2 点完搜索立刻数： 0 行
2 等列表刷新后再数： 2 行，第一行： SKU0001
3 下拉框选中： 杭州
4 弹窗文字： 确定清空吗？
4 点取消后： 你点了取消
5 iframe 里的文字： frame
6 新标签页里的文字： link

    六件事全在里面：登录、搜索等待、下拉框、弹窗、iframe、新标签页。下面逐个对照 Playwright 讲。

    12.3 定位：By 的八种方式¶

    Selenium 找元素统一用 driver.find_element(By.方式, "值")，找多个用 find_elements（返回列表，找不到给空列表，不报错）。八种方式和 Playwright 的对照：

    By 什么时候用 Playwright 里的等价写法
    By.ID 元素有唯一 id，最优先用 page.locator("#keyword")
    By.NAME 表单控件常有 name page.locator("[name=keyword]")
    By.CSS_SELECTOR 复杂结构，和第 9 章的 CSS 语法完全一样 page.locator("css=...")
    By.XPATH 要按文本或轴找的时候（第 9 章 9.4 节的语法） page.locator("xpath=...")
    By.CLASS_NAME 只有一个类名时；类名带空格不能用它的 page.locator(".search")
    By.TAG_NAME 按标签找，很少单独用 page.locator("table")
    By.LINK_TEXT 链接文字完全一致 page.get_by_role("link", name="...", exact=True)
    By.PARTIAL_LINK_TEXT 链接文字包含即中 page.get_by_role("link", name="...")

    练习网站页面都写了 data-testid 属性，Selenium 没有 get_by_test_id，用属性选择器找：By.CSS_SELECTOR, "[data-testid=welcome]"。

    第 9 章讲的定位策略取舍在这里照样成立：语义定位优先，脆定位躲着走，只是可选的词变了。

    和 Playwright 有一个重要差别：find_element 找不到立刻抛 NoSuchElementException；find_elements 找不到返回空列表。所以「这个提示可能不出现」这类断言，更干净的写法是用 find_elements 判列表长度，比 find_element 套 try/except 清楚。

    12.4 等待（重点）¶

    Playwright 的自动等待帮你挡掉了 UI 自动化最常见的一类偶发失败；Selenium 默认什么都不等，元素没出现就立刻报错。先看两个必然踩到的报错，scratch/selenium_traps.py：

    """演示 Selenium 的两个经典报错：元素还没出现就去找；页面刷新后还拿着旧元素。"""
from selenium import webdriver
from selenium.common.exceptions import NoSuchElementException, StaleElementReferenceException
from selenium.webdriver.chrome.service import Service
from selenium.webdriver.common.by import By
from selenium.webdriver.support.ui import WebDriverWait

BASE = "http://127.0.0.1:8000"
driver = webdriver.Chrome(service=Service(r"D:\tool\chromedriver\chromedriver.exe"))

# 先登录
driver.get(f"{BASE}/login.html")
driver.find_element(By.ID, "username").send_keys("alice")
driver.find_element(By.ID, "password").send_keys("alice123")
driver.find_element(By.CSS_SELECTOR, "button[type=submit]").click()

# 报错 1：点完登录马上找商品页的元素，页面还没跳过去
try:
    driver.find_element(By.ID, "keyword")
    print("运气好，页面已经跳过去了")
except NoSuchElementException as e:
    print("报错 1：", type(e).__name__)

WebDriverWait(driver, 10).until(lambda d: d.find_elements(By.CSS_SELECTOR, "#rows tr"))

# 报错 2：先拿到第一行，再搜索一次（列表重新渲染），旧的那一行元素已经不在页面上了
first_row = driver.find_element(By.CSS_SELECTOR, "#rows tr")
driver.find_element(By.ID, "keyword").send_keys("耳机")
driver.find_element(By.CSS_SELECTOR, "#search-form button[type=submit]").click()
WebDriverWait(driver, 10).until(lambda d: len(d.find_elements(By.CSS_SELECTOR, "#rows tr")) == 2)
try:
    print(first_row.text)
except StaleElementReferenceException as e:
    print("报错 2：", type(e).__name__)

driver.quit()

    运行（本机实测三轮，输出稳定）：

    (.venv) > python scratch\selenium_traps.py
报错 1： NoSuchElementException
报错 2： StaleElementReferenceException
    • 报错 1：点完登录立刻找商品页的搜索框。点击返回时页面还没跳转，元素根本还不存在。Playwright 里不存在这个问题（click 自带跳转等待，定位器自动等元素出现）；
    • 报错 2：先拿到表格第一行的元素，搜索后列表整块重新渲染，原来那个元素已经「作废」，再去 .text 就报 StaleElementReferenceException（元素引用过期）。Playwright 的定位器是「每次都重新找」的描述，没有这个问题。

    Selenium 的应对是显式等待：WebDriverWait(driver, 秒数).until(条件)，条件满足立刻继续，到点不满足抛 TimeoutException。常用条件都在 expected_conditions 里（习惯缩写成 ec）：

    条件 什么时候用
    ec.url_contains("/products.html") 等页面跳转
    ec.presence_of_element_located((By.ID, "status")) 等元素出现在页面里
    ec.visibility_of_element_located((By.ID, "toast")) 等元素出现且可见
    ec.element_to_be_clickable((By.ID, "buy-ok")) 等元素可见且能点
    ec.alert_is_present() 等浏览器弹窗出现
    ec.number_of_windows_to_be(2) 等新标签页出现
    ec.text_to_be_present_in_element((By.ID, "result"), "成功") 等元素里出现指定文字

    等不到现成条件时自己写 lambda，比如「等列表刷新成 2 行」（12.2.3 的脚本第 2 段）：

    wait.until(lambda d: len(d.find_elements(By.CSS_SELECTOR, "#rows tr")) == 2)

    坑

    隐式等待。 driver.implicitly_wait(10) 是另一个等待机制：每次找元素找不到时全局默等 10 秒。它和显式等待混用时，超时时间会互相叠加，出现「明明 10 秒该超时，等了 20 秒才报错」的怪现象。存量代码里见到它别模仿，统一用显式等待；本教程的夹具里明确设了 implicitly_wait(0) 把它关掉。

    第 8 章 8.7 节的口诀在这里同样适用：等待的是「结果」，不是「时间」。time.sleep(2) 在两边都是要消灭的写法。

    12.5 常用操作对照¶

    12.2.3 的脚本覆盖了大部分场景，这一节按「Playwright 写法 → Selenium 写法」列个清单，写存量代码时当字典查：

    操作 Playwright Selenium
    输入（先清空） locator.fill("耳机") el.clear(); el.send_keys("耳机")
    逐字符输入 locator.press_sequentially("耳机") el.send_keys("耳机") 天生就是逐字符
    按键 locator.press("Enter") el.send_keys(Keys.ENTER)（from selenium.webdriver.common.keys import Keys）
    点击 locator.click() el.click()；右键、双击、拖拽这类组合动作在 ActionChains 里（见下）
    悬停 locator.hover() ActionChains(driver).move_to_element(el).perform()
    右键 / 双击 locator.click(button="right") / dblclick() ActionChains(driver).context_click(el) / double_click(el)，最后 .perform() 执行
    拖拽 mouse.down()/move()/up() ActionChains(driver).drag_and_drop_by_offset(el, 横向像素, 纵向像素).perform()
    下拉框 locator.select_option("hz") Select(el).select_by_value("hz")（还有 select_by_visible_text、select_by_index）
    勾选框 locator.check() / is_checked() el.click()；状态看 el.is_selected()
    浏览器弹窗 page.on("dialog", ...) 提前注册 弹窗出现后 driver.switch_to.alert，.accept() / .dismiss() / .send_keys("文字")
    iframe page.frame_locator("#f") driver.switch_to.frame("f")，用完 switch_to.default_content()
    新标签页 context.expect_page() driver.window_handles 列表 + switch_to.window(句柄)
    上传 set_input_files(路径) el.send_keys(文件的绝对路径)，不用点系统窗口
    下载 expect_download() 没有专门接口，点下载后自己等文件出现（或配浏览器选项改下载目录）
    截图 page.screenshot(path=...) driver.save_screenshot("reports/shot.png")

    两个值得单独演示的：上传和截图。上传用的测试图片不能随手拼，PNG 有格式校验，用一个小脚本生成（顺便练一下二进制文件的写法）：

    """生成一张 1×1 像素的 PNG 图片，给上传头像的用例当测试文件用。只用 Python 自带的库。

运行：python tools/make_png.py data/avatar.png
"""
import struct
import sys
import zlib
from pathlib import Path


def chunk(kind: bytes, body: bytes) -> bytes:
    """PNG 文件由若干「块」组成：长度、类型、内容、校验码。"""
    return struct.pack(">I", len(body)) + kind + body + struct.pack(">I", zlib.crc32(kind + body))


def make_png(width=1, height=1) -> bytes:
    header = struct.pack(">IIBBBBB", width, height, 8, 6, 0, 0, 0)   # 8 位色深，RGBA
    pixels = b"".join(b"\x00" + b"\x5c\x6b\xc0\xff" * width for _ in range(height))   # 每行前面一个 0 表示不压缩
    return b"\x89PNG\r\n\x1a\n" + chunk(b"IHDR", header) + chunk(b"IDAT", zlib.compress(pixels)) + chunk(b"IEND", b"")


if __name__ == "__main__":
    target = Path(sys.argv[1] if len(sys.argv) > 1 else "data/avatar.png")
    target.parent.mkdir(parents=True, exist_ok=True)
    target.write_bytes(make_png())
    print(f"已生成 {target}，{target.stat().st_size} 字节")

    运行 python tools\make_png.py data\avatar.png 生成 data/avatar.png（70 字节），然后在已登录的浏览器里：

    driver.get(f"{BASE}/profile.html")
driver.find_element(By.ID, "avatar-file").send_keys(str(Path("data/avatar.png").resolve()))   # 绝对路径
driver.find_element(By.ID, "avatar-upload").click()
wait.until(ec.text_to_be_present_in_element((By.ID, "avatar-msg"), "上传成功"))
print(driver.find_element(By.ID, "avatar-msg").text)        # 上传成功（0.1 KB）
driver.save_screenshot("reports/profile.png")               # 整页截图，报告里当证据

    本机实测输出：上传成功（0.1 KB），截图 31742 字节。

    坑

    弹窗处理两边顺序相反。 Playwright 要在点按钮之前注册 dialog 处理器；Selenium 是弹窗出现之后再 switch_to.alert。Selenium 还有第三种状态：弹窗没人管，你去操作页面上的其他元素，会抛 UnexpectedAlertPresentException，弹窗被自动当成「取消」处理掉（本机实测：结果区显示「你点了取消」）。看到这个报错，先想想是不是有个弹窗没处理。

    12.6 写成 pytest 用例¶

    Playwright 有官方的 pytest 插件（第 11 章 11.1 节），Selenium 没有现成的，浏览器的启动和关闭自己写成夹具。新建 tests/selenium/conftest.py：

    """Selenium 用例的夹具。Selenium 没有官方的 pytest 插件，浏览器的启动和关闭自己写。"""
import os

import pytest
from selenium import webdriver
from selenium.webdriver.chrome.service import Service
from selenium.webdriver.support.ui import WebDriverWait


@pytest.fixture
def driver():
    """每条用例一个新浏览器，用完关掉。

    环境变量 CHROMEDRIVER 指向手动下载的 chromedriver.exe；没设就交给 Selenium 自己找（12.2 节）。
    默认无头运行（不弹窗口），想看着它跑就设环境变量 HEADED=1。
    """
    path = os.getenv("CHROMEDRIVER")
    options = webdriver.ChromeOptions()
    if os.getenv("HEADED") != "1":
        options.add_argument("--headless=new")
    d = webdriver.Chrome(service=Service(path) if path else Service(), options=options)
    yield d
    d.quit()


@pytest.fixture
def wait(driver):
    """显式等待的工具：wait.until(条件)，最多等 10 秒。"""
    return WebDriverWait(driver, 10)


@pytest.fixture
def logged_in(driver, wait, base_url, account):
    """已登录、停在商品页的浏览器。"""
    from selenium.webdriver.common.by import By
    from selenium.webdriver.support import expected_conditions as ec

    driver.get(f"{base_url}/login.html")
    driver.find_element(By.ID, "username").send_keys(account["username"])
    driver.find_element(By.ID, "password").send_keys(account["password"])
    driver.find_element(By.CSS_SELECTOR, "button[type=submit]").click()
    wait.until(ec.url_contains("/products.html"))
    # 再等首屏的商品列表加载出来：页面准备好了再交给用例，免得用例在页面没就绪时就开始操作
    wait.until(lambda d: d.find_elements(By.CSS_SELECTOR, "#rows tr"))
    return driver

    三条用例，都和前面章节用 Playwright 写过的同类一一对应：

    """用 Selenium 写的三条用例，和第 8、11 章 Playwright 写的同类用例对照着看。"""
from selenium.webdriver.common.by import By
from selenium.webdriver.support import expected_conditions as ec

ROWS = (By.CSS_SELECTOR, "#rows tr")


def test_login_shows_welcome(logged_in, account):
    assert logged_in.find_element(By.ID, "welcome").text == f"欢迎，{account['username']}"


def test_search_headphones(logged_in, wait):
    logged_in.find_element(By.ID, "keyword").send_keys("耳机")
    logged_in.find_element(By.CSS_SELECTOR, "#search-form button[type=submit]").click()
    wait.until(lambda d: len(d.find_elements(*ROWS)) == 2)      # 等列表刷新成 2 行
    assert all("耳机" in row.text for row in logged_in.find_elements(*ROWS))


def test_confirm_dismiss(driver, wait, base_url):
    driver.get(f"{base_url}/lab.html")
    driver.find_element(By.ID, "btn-confirm").click()
    wait.until(ec.alert_is_present()).dismiss()
    wait.until(ec.text_to_be_present_in_element((By.ID, "result"), "你点了取消"))

    几个细节值得注意：

    • 默认无头运行：和第 11 章 Playwright 的用例一样，平时不弹浏览器窗口；想看着它跑，先设 $env:HEADED = "1" 再运行，用完 Remove-Item Env:HEADED；

    • logged_in 多等了一步：跳到商品页之后，再等首屏的商品列表出现才交给用例。Selenium 不会自动等页面准备好，夹具里把这一步做掉，每条用例就不用各写一遍；

    • 每条用例都新开一个浏览器进程（夹具是 function 作用域），3 条用例 12.8 秒；对比第 11 章的 Playwright 用例，10 条只要 8.8 秒——Playwright 的插件每条用例新开的是轻量的标签页上下文，浏览器进程整轮只起一次。这是两边速度差距的主要来源；

    • base_url、account 夹具都是现成的（tests/conftest.py），Selenium 的用例直接复用，配置、账号、接口造数那套完全不用改。工程化的部分是工具无关的，这正是分层带来的好处。

    页面对象模式在 Selenium 里同样适用：第 11 章 11.2 节的 LoginPage 把 page.locator(...) 换成 driver.find_element(By.ID, ...)，其余一行不用动。

    12.7 Selenium 与 Playwright 怎么选¶

    维度 Playwright Selenium
    环境准备 pip install + 自带浏览器下载，开箱即用 要维护 chromedriver 和浏览器版本的配套
    自动等待 默认等待元素就绪，偶发失败少 什么都不等，全靠显式等待，写不好就偶发失败
    速度 浏览器进程复用，明显更快 每条用例一个浏览器进程，偏慢
    调试工具 追踪回放、逐行暂停、录制生成代码 只有简单的日志
    支持的浏览器 Chromium 系、Firefox、WebKit 几乎所有浏览器，包括一些老版本和 IE 模式
    多语言 Python、Java、JavaScript、.NET 语言更多，Java 生态尤其成熟
    生态与存量 新项目的主流选择 存量项目极多，国内招聘要求的常客

    给三个具体建议：

    • 新项目：选 Playwright。自动等待和环境这两点就能省掉大量的维护成本；
    • 存量 Selenium 项目：没必要为了换而换。按第 11 章的页面对象把代码理顺，性价比更高；
    • 要同时维护两边：把公共的东西（配置、账号、接口造数、页面对象的接口）做成工具无关的，两边各自只保留薄薄一层「操作页面」的代码。本教程的工程结构天然支持这么做。

    12.8 常见的坑¶

    现象 原因与解决
    NoSuchDriverException: Unable to obtain driver for chrome Selenium Manager 下载不了 chromedriver（网络问题）。按 12.2.2 手动下载，Service() 指定路径
    session not created: Chrome version must be ... Chrome 升级了，chromedriver 版本没跟上。下载配套版本覆盖
    元素明明在页面上，find_element 却报 NoSuchElementException 元素在 iframe 里，先 switch_to.frame()；或者在 shadow DOM 里，要先取元素的 shadow_root 再在里面找
    时好时坏的 NoSuchElementException 没等页面刷新完。补显式等待，等的是条件不是时间
    StaleElementReferenceException 拿到的元素在页面重新渲染后作废了。重新 find_element，别缓存元素对象
    UnexpectedAlertPresentException 有个浏览器弹窗没人处理。用 ec.alert_is_present() 等它出现，accept 或 dismiss 之后继续
    切进 iframe 出不来 后面的定位全找的是 iframe 里的东西。用完立刻 switch_to.default_content()
    用例越来越慢 每条用例起一个浏览器进程是主因；再检查有没有该用显式等待的地方写成了长 time.sleep
